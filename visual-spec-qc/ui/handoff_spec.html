Figma 交付檔案整理規範

讓設計稿能被「切版核對工具」自動比對的檔案整理方式。照這份整理,QC 工具就能一鍵核對設計與網站,並自動分辨差異是設計還是程式的責任。

適用　網站頁面設計交付對象　設計師搭配工具　Visual & Spec QC
核心原則 · The One Rule

一個可定址的 Frame ＝ 一頁 × 一個尺寸 ＝ 對應 一個 URL @ 一個瀏覽器寬度

01

Frame 命名 = 路由 ＋ 寬度

尺寸標準測試寬度Frame 命名範例
桌機 Desktop1440/about @1440
平板 Tablet768/about @768
手機 Mobile375/about @375
🎯 為什麼固定這三個寬度?　工具會把瀏覽器設成 frame 名稱裡的寬度再抓網頁。用 768 / 375 這種範圍內的代表值,而不是斷點邊緣值(如 576),可避免剛好卡在臨界點造成的抖動。Frame 畫布寬度請 = 命名的寬度。
02

檔案結構:一頁一 Page,三尺寸並列

▚ Page：About # 一個網站頁面 = 一個 Figma Page ├─ 🖼 /about @1440 # 交付 frame(桌機) │ ├─ sec:hero │ ├─ sec:seo-cards │ ├─ sec:iso │ └─ sec:footer ├─ 🖼 /about @768 # 平板:用同一組 sec:key │ └─ sec:hero / sec:seo-cards / … └─ 🖼 /about @375 # 手機:用同一組 sec:key └─ sec:hero / sec:seo-cards / … ▚ Page：_工作區 # 草稿 / popup / FAQ schema 文字 → 放這,不交付
📁 三個尺寸都是 top-level frame(不要巢狀在難定址的 instance 裡),尺寸靠命名區分,不要靠旁邊另畫的文字標籤。
03

單元 Key ↔ 前端對照(最關鍵)

在源頭解決「節點對位」
Figma 圖層命名
sec:hero
→
前端 HTML 標註
data-figma-id="sec:hero"
→
QC 工具
自動對位
無需人工
三個尺寸的同一單元都叫 sec:hero → 工具就懂「這是手機版的 hero」。
設計命名 + 前端標註對齊,對位就在源頭完成,QC 才能真正一鍵跑完。
🤝 這需要設計與前端約定同一組 key。key 用小寫、語意化、跨尺寸一致:sec:hero、sec:seo-cards、sec:iso、sec:footer…(或改用 Figma Code Connect 綁定,效果相同)。
04

現在 → 改成(依實際檔案)

現在的做法
  • 命名不一致 index_1440 / index / index_380,寬度與斷點標籤對不上
  • 尺寸靠旁邊另畫的文字標籤區分
  • 隱藏 FAQ 文字、popup 混在交付 section 裡
  • 部分顏色/字級直接填色碼(hardcode)
建議改成
  • 統一 /about @1440 · @768 · @375
  • 尺寸靠 frame 命名區分,標籤免了
  • 草稿/隱藏內容移到 _工作區 Page
  • 顏色/間距/字級全綁 Variable(token)
🎨 為什麼要綁 Variable?　凡是綁了 token 的屬性,實作沒對齊 → 工具判「程式要修」;沒綁、hardcode 的 → 判「設計稿規格待補」丟回設計端。綁好 token,責任歸屬才準。
05

交付前 Checklist

點一下打勾
  • ✓每個交付頁 = 一個 Figma Page
  • ✓每頁含 3 個尺寸 frame,命名 /route @width
  • ✓三個尺寸使用同一組 sec:key
  • ✓已與前端約定 data-figma-id 對照
  • ✓顏色 / 間距 / 字級皆綁 Variable,無 hardcode
  • ✓草稿 / 隱藏內容已移出交付 section
  • ✓交付時提供 prototype 連結 ＋ 對應網站 base URL
